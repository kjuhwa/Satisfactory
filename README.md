# Satisfactory 작업 공간

- **공장 플래너** (`web/`) — 생산 계획 웹 앱 (아래 설명)
- **효율 헬퍼** (`helper/`) — **실제 스팀 게임 플레이용** 계산기. 매장지 순도(임순/보통/순수)와
  채굴기 Mk·클럭을 넣으면 채굴량에 딱 맞는 벨트 티어, 목표 아이템까지 단계별 기계 대수와
  언더클럭 %(어느 기계도 놀지 않는 세팅), 동력 조각으로 대수를 줄이는 대안, 총 전력을 계산한다.
  순도×채굴기 조합별 "딱 맞는 벨트" 빠른 표 포함 (예: 보통+Mk.2=120/분 → Mk.2 벨트 딱).
  각 단계마다 **분배기 배치 가이드**를 붙인다 — 대수가 2·3의 곱이면 균형 트리(분배기
  몇 개를 어떤 분기로 겹치는지), 아니면 매니폴드(일렬) 안내와 "예열되면 균등해진다"는
  설명, 그리고 균형 트리가 가능한 대수로 늘리는 대안 클럭까지. 합류기 개수도 표시.
  **부산물 재사용 계산** 포함 — 알루미나 공정의 이산화규소·알루미늄 조각의 물처럼
  부산물을 라인 입력으로 되돌리는 만큼 원자재와 기계 수가 줄어든 세팅을 낸다
  (반복 수렴 계산, 잉여 부산물은 별도 표시).
  물(양수기 120㎥/분 고정)·원유(추출기, 순도 적용) 같은 액체 자원도 지원하며
  액체 구간은 파이프 Mk.1(300)/Mk.2(600) 기준으로 계산한다(접합 자연 균형 안내).
  각 단계는 실제 짓는 모양 그대로의 **배치도**(추출기 → 분배 라인 → 기계 배열 → 합류
  → 출력, 벨트는 점선·파이프는 파란 실선)로 그려진다. 분배기·합류기·파이프 접합은
  실물 게임 아이콘으로, 개수는 실배치 그대로(N대면 분배기 N−1개, 마지막 기계는 벨트 끝 직결).
  대체 레시피 선택 지원(기본값은 그 아이템이 주 산출물인 정규 레시피), 벨트 Mk.6(1200/분)까지.
  **해금된 벨트/파이프 티어 설정** — 초반이라 Mk.1뿐이면 모든 추천이 Mk.1 기준으로 바뀌고,
  채굴기 출력 포트는 하나라는 실게임 제약대로 순수 매장지도 벨트 한도가 실효 상한이 된다
  (병목 경고 + 같은 양을 캐며 전력만 아끼는 언더클럭 제안, 한도 초과 유량은 여러 줄 분할 안내).
  부수 원자재도 편법 없이 **정석으로 전부 채굴 계획**에 포함한다 — 강철에 드는 석탄,
  알루미늄에 드는 물·석영까지 채굴기/양수기 대수·클럭·전력을 계산해 카드로 붙인다
  (부수 매장지도 주 매장지처럼 "직접 구성"으로 여러 개 등록 가능 — 매장지마다 순도·채굴기
  Mk를 고르면 필요량을 균등 클럭으로 자동 배분하고, 용량이 모자라면 부족량 경고). 결과 마지막의 **전체 배치도**는 위에 그려진
  채굴·단계 배치도를 그대로 세로로 이어 붙인 합성 청사진이다 — 단계 사이 연결선은
  오른쪽 레인을 타고 소비 공정의 입력 라인까지 내려가고, 부산물 재순환은 초록 ♻ 점선.
  **수송 가이드** — 매장지가 멀 때를 위해 단계별 벨트 부하를 광석 대비 %로 표시
  (주괴 1:1은 수송 이득 없음, 철판 50%·보강판 8% 같은 압축 단계까지 현지 가공 후 나르기,
  벨트 무손실·트럭 티어3·기차 티어6 안내).
  커뮤니티 정석 반영 — 인젝티드 매니폴드(중간 주입, 예열 절반) 안내, 동력 조각은
  채굴기 우선 원칙, 전력 저장고 권장 수(피크 여유 20%), 단계별 **청사진 분할**
  (기계 실측 바닥 크기로 설계기 Mk.1~3 한 장당 대수와 필요 장수 계산).
  **발전소 계획** — 총 전력을 보고 발전 방식(석탄/연료/터보/원자력)별 발전기 대수,
  연료 소모, 연료 생산 라인(정제 체인·원자재 추출 포함)까지 설계 — 연료 라인이 쓰는
  전력도 발전기 대수에 반영될 때까지 반복 수렴. **대체 레시피 자동 추천**(주 자원
  소모가 5% 이상 줄면 단계 카드에 표시), **공유 링크**(설정 전체를 URL 해시로),
  **잉여 부산물 싱크 포인트**(pt/분, 액체는 싱크 불가 표기), **티어 프리셋**(진행
  티어 선택 → 벨트/파이프 해금 일괄 설정).
  **지도 자원 한계 검증** — 1.0 실측 매장지 수(자원·순도별)를 내장해, 한 매장지에
  채굴기 1대라는 제약대로 "매장지 N곳 필요 vs 맵 전체 M곳" 검증. 필요량이 지도
  이론상 최대(전 매장지 Mk.3 250%)를 넘으면 물리적 최소 완료 시간을 계산해 경고.
  **미션 모드** — HUB 마일스톤 42개(게임 데이터)와 우주 엘리베이터 1~5단계(1.0 수치)를
  고르고 목표 완료 시간을 정하면, 요구 물품 전부를 그 시간 안에 동시에 만들어내는
  공장(원자재 채굴 계획부터 전체 배치도까지)을 통째로 설계한다.
  플래너(`web/`)가 "목표량→역산"이라면
  이쪽은 "가진 매장지→최대 활용" 순방향이다. `helper/index.html` 로 실행.
- **방치형 공장 게임** (`game/`) — 실제 1.0 레시피·전력·건설 비용 밸런스로 돌아가는
  브라우저 공장 건설 게임. `game/index.html` 을 열면 실행. 2D 캔버스에 채굴기·기계·발전기
  노드를 배치하고 출력→입력 포트를 드래그로 연결해 생산 체인을 설계한다 (버퍼·배압·전력
  부족 감속 시뮬레이션). 컨베이어 벨트 티어(Mk.1 60/분 ~ Mk.5 780/분, 연결선 클릭으로
  업그레이드), 자원 매장지 제한 + 순도(불순 ×0.5 / 보통 ×1 / 순수 ×2), 휠 줌,
  AWESOME 싱크(아이템 소각 → 포인트 → 쿠폰 자동 발행) + 상점(동력 조각·하드 드라이브),
  노드 오버클럭(50~250%, 전력 지수 1.32), 대체 레시피 하드 드라이브 3택1 해금,
  원자력 발전(2,500MW, 폐기물이 안 빠지면 정지 — 소각 불가라 재처리 라인 필수),
  채굴기 Mk.1~3(60/120/240, 마일스톤 해금), 노드 복제, 공장 통계 패널,
  계획 모드(목표 아이템 → 필요 라인 계산 → 캔버스 자동 배치),
  마일스톤 12개(프로젝트 조립 1~5단계), 시작 가이드, 효과음,
  자동화(기계 자동 구매·마일스톤 자동 달성·벨트 자동 업그레이드·동력 조각 자동 교환),
  공장 설계 JSON 내보내기/가져오기 지원.
  출하 노드에 연결된 아이템만 재고로 들어오고, 그 재고로 마일스톤 8개를 달성하는 것이 목표.
  localStorage 자동 저장 + 오프라인 진행(최대 4시간).
  `node game/server.js` 로 저장 서버를 띄우면 진행 상황이 서버에 저장되어
  다른 기기·다른 브라우저에서 이어서 할 수 있다 (아래 "저장 서버" 참고).
- **공장 단지 게임 (실험판)** (`game2/`) — 위 게임의 UI 재설계 버전. 시설 카드를 다른
  카드 위로 드래그하면 하나의 "단지"로 합체되고(석탄 채굴+물 추출+발전기 = ⚡ 석탄 발전

  마일스톤·상점·오버클럭·데이터를 공유하되 저장은 별도.

  아래 "빚과 칼" 참고.

  **미니 세션 게임** (Mini Metro식). 발전소(출력만)와 자라나는 도시(입력만)를 한정된
  전선으로 이어 정전을 막는다. 한 판 10분 내외, 드래그 하나로 조작, 폰 우선 설계.
  며칠마다 보급 3택1(발전소/전선/변전소), 최고 기록은 localStorage.
  2일차부터 **공장**이 나타난다 — 전력을 이어 주면 아이템(부품/전지/모터)을 만들고,
  완성품은 즉시 어드밴티지로 자동 변환된다(전선 +1 / 모든 도시 정전 게이지 -40% /
  무작위 발전소 +3MW). 공장은 잔여망 2차 최대유량으로 **도시가 쓰고 남는 전력만**
  가져가므로 이어도 도시는 안전하고, 아이템 3개를 만들면 철수하며 전선을 돌려준다.

  노드는 고정되어 있고 플레이어는 전선만 잇는다. 색 소스(빨/노/파)를 혼합기(두 색 → 주황/초록/보라,
  같은 색은 합류)·분배기(균등 분할, 최대 3갈래)·증폭기(×2)로 가공해 목표 수치를 채운다.
  전선을 적게 쓸수록 별(1~3)이 늘고, 후반 레벨은 기계 전력 합계에 한도가 있어
  어느 기계를 안 쓸지도 퍼즐이다. 레벨 10개, 별 기록은 localStorage.
  `flowpuzzle/index.html` 단독 실행, 폰 우선 설계.

# 빚과 칼 (`quests/`)

D&D 풍 세계에서 상황별 선택지를 고르는 텍스트 RPG. 전투 화면이 아니라 선택형 소설에 가깝고,
**능력치·소지품·재산·지난 선택**에 따라 열리는 선택지와 결과가 달라진다.
`quests/index.html` 을 열면 실행된다 (서버 불필요).

**한 판 = 서른 날.** 빚 240금을 기한 안에 갚으면 이기고, 몸이 버티지 못하거나 기한을 넘기면 진다.
죽으면 거기서 끝이지만, 그 판에서 한 일이 **기억**으로 남아 다음 판의 시작 조건이 된다.

## 이 장르가 지루해지는 지점을 피하려고 정한 것 셋

**1. 잠긴 선택지를 지우지 않는다.** 무엇이 얼마나 모자라 못 고르는지 같이 적는다.

```
 1. 돈을 낸다 (금화 -30)
 2. 싸운다                      성공 55%
 3. 깎아 본다                   말솜씨 12 필요 · 지금 9      ← 회색으로 남는다
 4. [아는 얼굴] "그때 그 얼굴이군."
```

못 고르는 선택지가 보여야 능력치를 올릴 이유가 생긴다. 이 장르에서 제일 자주 빠지는 요소다.

**2. 과거가 되돌아온다.** 선택은 흔적(flag)을 남기고, 뒤쪽 사건이 그 흔적을 조건으로 갈라진다.
3일째에 놓아준 좀도둑이 20일째 길목에서 통행을 터 준다. 관에 넘겼다면 패거리가 기다리고 있다.
사이드바의 "지나온 일"에 며칠째에 무엇을 했는지가 그대로 쌓인다.

**3. 실패가 죽음이 아니다.** 판정에 실패해도 이야기는 다른 쪽으로 이어지고,
쓴 능력치는 실패해도 가끔 는다("몸으로 배웠다"). 실패가 순수 손해이기만 하면 아무도 시도하지 않는다.

## 수치는 자동 플레이로 맞췄다

봇 500판씩 돌려 조정했다. 처음에는 최대 체력 12에 한 방이 -5~-7이라 회복이 못 따라갔고
사망률이 90%를 넘겨 "선택"이 아니라 "운"만 남아 있었다.

| 두는 방식 | 승 | 사망 | 기한 초과 |
|---|---|---|---|
| 무작위로 고름 | 8.8% | 54.8% | 36.4% |
| 기대값을 계산해서 고름 | 86.8% | 12.8% | 0.4% |

**10배 차이**가 나야 선택이 장식이 아니다. 이 표가 그 확인이다.
빚 액수를 올려도 잘 두는 쪽은 83%→73%밖에 안 떨어지고 못 두는 쪽만 무너졌는데,
돈이 아니라 **생존**이 병목이라는 뜻이라 빚은 240에서 멈췄다.

```
quests/engine.js   규칙 — 조건 평가 · 판정 · 효과 적용 · 하루 진행 (내용을 모른다)
quests/events.js   내용 — 사건 40개 · 소지품 13종 · 기억 6종
quests/ui.js       화면 — 잠긴 선택지 표시, "지나온 일" 기록
```

`engine.js` 는 내용을 모르고 `events.js` 는 규칙을 모른다. 사건을 추가할 때 엔진을 건드릴 일이 없다.

> 장르만 참고했을 뿐 특정 게임의 내용을 옮긴 것이 아니다. 사건·수치·문장 전부 이 저장소에서 쓴 것이다.

# 개척 원정대 (`frontier/`)

앞의 세 개는 전부 숫자 패널이다 — 트리를 계산하거나, 노드를 배치하거나, 규칙을 편집한다.
이쪽은 **공간과 명령어**다. 여럿이 같은 행성에 강하해서, 좋은 자리를 먼저 잡는 게임이다.

```
> 북
철광 능선
붉게 녹슨 능선이 길게 뻗어 있다. 노두가 통째로 철광석이다.
다만 능선 위라 물 한 방울 없다 — 전력은 아래에서 끌어와야 한다.
출구: 동(???)  서(???)  위(???)  남(숲 가장자리)

> 조사
  [1] 철 광석 · 순수 (×2) — 비어 있음
  [2] 철 광석 · 순수 (×2) — 아리 점유
```

## 이 게임이 걸고 있는 것 하나

**지역마다 강점과 대가가 반드시 어긋난다.** 순도 높은 매장지일수록 멀고, 위험하고, 물이 없다.
물이 없으면 그 자리에서 발전할 수 없으므로 **송전탑으로 전력을 끌어와야** 한다.
그래서 순수 철 매장지가 셋이나 있는 `하늘 고원` 은 최고의 자리인 동시에 최악의 자리다.

매장지는 **선착순**이다. 24개 지역에 흩어진 좋은 자리는 정해져 있고, 남이 먼저 잡으면 끝이다.
그래서 이 게임의 진짜 자원은 광물이 아니라 자리다.

## 규칙

- 지역 24개, 위험 등급 0~3. 등급 2 이상은 **방호복 / 방독장비** 없이 들어갈 수 없다
- 전력망은 **송전탑으로 이은 지역끼리만** 하나다. 본거지가 속한 망에만 캡슐 원자로 100MW 가 들어온다
- 물이 있는 지역에만 석탄 발전기를 세울 수 있다
- 재고는 플레이어 단위로 공유된다(물류는 추상화). 제약은 **전력과 자리**에 걸린다
- 자리를 비운 동안에도 공장은 돈다 (최대 8시간까지 따라잡는다)
- 우주 엘리베이터는 3단계 공동 프로젝트다. 여럿이 붙는 서버에서는 **혼자서 못 짓는 양**이고,
  혼자 하는 모드에서는 필요량이 5분의 1로 줄어 있다

## 명령어

| 명령 | 설명 |
|---|---|
| `북` `남` `동` `서` `위` `아래` | 이동 (`n` `s` `e` `w` `u` `d` 도 된다) |
| `보기` `조사` `지도` | 살펴보기 · 매장지 드러내기 · 발견한 지역 |
| `점유 <번호>` | 매장지 선점 (선착순) |
| `건설 채굴기 <번호>` | 점유한 매장지에 추출 설비 |
| `건설 발전기` · `건설 물펌프` | 물이 있는 지역만 |
| `건설 <레시피> [수]` | 가공 라인 (예: `건설 철판 2`) |
| `송전 <방향>` | 인접 지역과 전력망 연결 |
| `제작 방호복` · `제작 방독장비` | 위험 지역 진입 장비 |
| `회수` | 잔해에서 하드 드라이브·유물 |
| `공장` `재고` `전력` | 내 상태 |
| `목표` `납품 <품목> <수>` | 공동 프로젝트 |
| `말` `외침` `누구` | 같은 지역 / 전 세계 / 접속자 |

## 실행 — 두 가지 모드

켜질 때 서버가 있는지 스스로 확인하고 알아서 갈라진다.

| | 혼자 (서버 없음) | 여럿 (서버 있음) |
|---|---|---|
| 여는 법 | `frontier/index.html` 을 열기만 하면 된다 (**GitHub Pages 에서 그대로 돌아간다**) | `node game\server.js` → `http://localhost:8787/frontier/` |
| 세계가 도는 곳 | 브라우저 | 서버 (접속을 끊어도 계속 돈다) |
| 저장 | 이 브라우저의 localStorage | `game/saves/frontier-world.json` |
| 다른 사람 | 없다 — 매장지 경쟁도 없다 | 같은 행성을 나눠 쓴다 |
| 공동 프로젝트 | 필요량이 **5분의 1** 로 줄어 있다 | 통째로 (혼자서는 못 끝낸다) |

규칙은 양쪽이 **같은 `core.js`** 를 쓴다. 지도·전력망·순도·건설비가 갈라질 수 없다.

```
frontier/core.js    규칙 전부 (환경 의존 없음 — fs 도 http 도 쓰지 않는다)
frontier/map.js     지역 24개 + 지도 검증기
frontier/world.js   Node 어댑터 — HTTP/SSE · 파일 저장 · 세계 시계
frontier/local.js   브라우저 어댑터 — localStorage 저장 · 브라우저 시계
frontier/client.js  터미널 UI · 모드 자동 감지
```

서버 모드는 저장 서버와 같은 프로세스를 쓴다 (`/api/mud/*`). 점유·건설처럼 되돌릴 수 없는
결정은 명령 직후에 저장하고, 쌓인 생산량은 저장 시각으로부터 다시 계산한다
(그래서 몇 초쯤 잃어도 복구된다). 꺼져 있던 시간은 최대 8시간까지 따라잡는다.

> 서버→클라는 SSE, 클라→서버는 POST 다. WebSocket 라이브러리를 쓰지 않으려고 고른 조합이라
> 이 저장소의 "의존성 0" 원칙이 그대로 유지된다.

# 규칙 공장 (`rulefactory/`)

기존 게임이 "노드를 놓고 선을 잇는" 배치 게임이라면, 이쪽은 **규칙을 짜는 게임**이다.
플레이어는 기계를 직접 사지 않는다. `조건 → 행동` 규칙을 만들어 두면 컨트롤러가 대신 짓는다.

```
만약  재고   철 광석  <  400  이면  →  채취기 증설   철 광석 ×1   (쿨다운 8초)
만약  전력 여유(%)    <  15   이면  →  발전기 증설   석탄 발전기 ×1
만약  주기(초)마다    30            →  계약 납품
```

## 핵심 제약: 제어 대역폭

규칙은 매 틱 **위에서부터** 평가되고, 평가에 1 · 발동에 3 만큼 대역폭을 쓴다.
대역폭이 바닥나면 **아래쪽 규칙은 그 틱에 아예 평가되지 않는다** (화면에 "대역폭 부족"으로 표시).
따라서 이 게임의 실력은 *규칙 순서와 쿨다운 배분*이다. 대역폭은 연구로 늘린다.

밀린 규칙은 **다음 틱에 우선권을 갖는다** (그 규칙부터 시작해 한 바퀴 돈다).
그래서 대역폭이 모자라면 아래쪽 규칙은 *느려질* 뿐, 영영 멈추지는 않는다.
이 보정이 없으면 `규칙 위치 + 3 > 대역폭` 인 규칙은 조건이 아무리 맞아도 영구히 발동하지 못한다.

- **조건**: 재고 · 순생산(/분) · 전력 여유(%) · 라인 가동률(%) · 크레딧 · N초 주기 · 항상
- **행동**: 생산 라인 증설 · 채취기 증설 · 발전기 증설 · 재고 소각(→크레딧) · 연구 구매 ·
  계약 납품 · **다른 규칙 켜기/끄기**(규칙이 규칙을 제어하는 메타 규칙)
- **성장**: 계약 납품 → 크레딧 → 연구(대역폭·규칙 슬롯·기계 해금) → 더 복잡한 규칙
- 오프라인(기본 4시간, 연구로 12시간) 동안에도 규칙이 그대로 돈다
- 같은 재료를 쓰는 라인이 여럿이면 모자란 재료는 **요구량 비율대로 나눠 갖는다**.
  한 라인이 재고를 독점해 다른 라인이 0개로 굶는 일은 없다 (다 같이 느려질 뿐이다)

## 시작

이 게임에는 수동 채집·수동 제작이 없으므로, 새로 시작하면 **시작 지원 물자**(철판·철봉·콘크리트·
전선·케이블·보강 철판·회전자)와 **철 광석 채취기 1대**가 주어진다. 규칙 패널의 **"예시 규칙 넣기"** 를 누르면
스스로 돌아가는 최소 순환이 **13개 규칙**으로 채워진다 — 철·구리·석회석 채취 → 주괴 →
철판·철봉·나사·전선·케이블·보강 철판·콘크리트 → **계약 납품**까지 한 바퀴가 닫혀 있다.
그대로 두면 30분 안에 1차 납품이 자동으로 끝난다. 이후는 수치를 바꾸고 규칙을 추가하며 키우면 된다
(2차 납품에는 회전자가 필요한데 회전자 라인 규칙은 일부러 비워 두었다 — 남은 슬롯으로 직접 짜 보라는 뜻).

건설비가 순환한다는 점이 중요하다: 제작기는 보강 철판·케이블로 짓고, 제련기는 철봉·전선으로,
채굴기는 철판·철봉·콘크리트로 짓는다. 그래서 전선·케이블·나사·보강 철판 라인이 빠진 규칙 세트는
밑천을 다 쓴 뒤 기계를 한 대도 더 못 지어 공장이 통째로 멈춘다.

채취기가 하나도 없고 채취기를 지을 자재도 없으면 새로 들어올 자원이 없어 영영 멈춘다.
그때만 공장 현황 패널에 **긴급 지원 물자** 버튼이 열린다 (막히지 않았을 때는 사용할 수 없다).

전력은 기본 100MW로 시작하며 기계 20대쯤이면 바닥난다 — 그 다음은 석탄 발전 연구가 필요하다.

**남는 전력보다 많이 먹는 기계는 지어지지 않는다** (규칙이 "전력 부족: 여유 0 / 필요 4MW" 로 막힌다).
이 제동이 없으면 전력이 모자라 라인이 감속 → 재고가 목표에 못 미침 → 규칙이 라인을 더 증설 →
전력이 더 모자라는 되먹임이 생겨 공장 전체가 느려지기만 한다. 발전기 증설은 이 제한을 받지 않는다.

저장은 기존 게임과 완전히 분리된다 (localStorage 키가 다르고, 서버 저장은 같은 코드의 다른 슬롯).
같은 플레이어 코드로 두 게임을 각각 이어서 할 수 있다.

# 방치형 공장 게임 — 배치 관리

공장이 커지면 캔버스가 금방 난장판이 된다. 툴바 오른쪽 세 버튼으로 정리한다.

| 버튼 | 동작 |
|---|---|
| 🧹 정리 | 연결 관계를 따라 원자재 → 가공 단계 → 출하 순으로 왼쪽부터 열을 맞춰 재배치 (직접 잡아둔 위치는 사라지므로 확인창을 띄운다) |
| ⤢ 화면 맞춤 | 모든 노드가 한 화면에 들어오도록 확대율과 스크롤을 맞춤 (최소 20%까지 축소) |
| 🔍 축소 표시 | 노드에서 건설 비용·속도·버퍼를 감추고 작게 표시 — 노드가 20개를 넘어가면 이쪽이 보기 편하다. 설정은 저장된다 |
| ⚡ 전력 회복 | 전력이 모자라 스스로 못 빠져나올 때. 발전기와 그 연료 라인만 남기고 하류부터 멈춘다 |
| ▶ 전부 재개 | 멈춰 둔 노드를 모두 다시 돌린다 |

# 방치형 공장 게임 — 병목 안내

노드가 100%가 아니면 그 이유를 노드에 적어 준다. 이 문구가 틀리면 플레이어는 정확히 반대로 움직인다.

실제로 그런 일이 있었다. 석탄 발전기 4대는 물 **180/분**이 필요한데 벨트가 Mk.2(**120/분**)면
발전기는 67%에서 멈춘다. 물은 상류에 남아돌지만 벨트가 못 나르는 것이다.
그런데 안내는 `연료 부족: 물 — 이전 단계 생산을 늘리세요` 라고만 했다.
그 말대로 물 추출기를 16대까지 늘리면 **전력이 320MW 씩 빨려 나가 공장 전체가 무너진다.**
발전기는 여전히 67%다.

지금은 들어오거나 나가는 벨트가 이미 꽉 찼는지 먼저 보고 갈라 준다:

```
벨트 한계: 물 120/분 → 180/분 필요 — 연결선을 클릭해 업그레이드하거나 하나 더 이으세요
```

벨트가 원인이 아닐 때는 예전대로 `이전 단계 생산을 늘리세요` 가 나온다.
같은 판정을 벨트 자동 업그레이드가 쓰던 기준(용량의 98%)과 똑같이 맞췄다.

## "잘 되다가 갑자기" 무너지는 것을 미리 알린다

이 게임에서 제일 잔인한 순간은 멀쩡하던 공장이 갑자기 주저앉는 것이다.
**들어오는 양보다 쓰는 양이 많아도 버퍼가 남아 있는 동안은 100% 로 보이기 때문이다.**

물 추출기 1대(120/분)에 석탄 발전기 5대(물 225/분 필요)를 물리면 분당 105 적자다.
그런데 발전기 버퍼 500이 그 적자를 3분쯤 가려 준다. 그동안은 아무 문제가 없어 보인다.
버퍼가 마르는 순간부터가 진짜다 — 시뮬레이터로 잰 실제 경과:

| 시각 | 발전기 | 전력 |
|---|---|---|
| 0~3분 | 100% | 348 / 395 MW |
| 4분 | 22% | 348 / **104** MW |
| 5분 | 8% | 348 / **49** MW |
| 이후 | 7% | 348 / 47 MW (고정) |

발전량이 떨어지면 전력이 모자라고, 전력이 모자라면 물 추출기가 느려지고,
그러면 발전량이 더 떨어진다. 한 번 넘어가면 **스스로 돌아오지 못한다.**

그래서 아직 100% 로 돌고 있을 때 미리 알려 준다 (노란색):

```
⏳ 물 적자 105/분 (들어옴 120 · 씀 225) — 약 3분 뒤 멈춥니다
```

들어오는 양과 쓰는 양을 같이 적어서 몇 대를 더 지어야 하는지 바로 계산된다.
균형이 맞는 공장에서는 아무 말도 하지 않는다 — 발전기를 한 대 더 지어 적자가 되는
그 순간에만 뜬다. 이미 무너진 뒤라면 ⚡ 전력 회복 으로 하류를 멈추고 되살리면 된다.

# 방치형 공장 게임 — 왜 버벅거렸나

켜 두고 제작을 이것저것 하다 보면 화면이 점점 버벅거리다 멈추는 일이 있었다.
시뮬레이션이 무거워서가 아니었다 — 320노드에서도 한 틱에 5ms 로, 200ms 예산의 2% 다.

범인은 **화면 전체를 다시 그리는 횟수**였다.

```js
// update() — 200ms 마다 돈다
if (visibleStock().join(',') !== stockKeys) { rebuild(); return; }   // ← 전체 DOM 재생성
```

재고 목록이 바뀌면 노드·포트·연결선을 통째로 다시 만든다. 그런데 수동 제작으로 재고를 쓰면
품목이 0 아래로 내려갔다가 다음 틱에 생산분이 들어오면서 다시 올라온다.
**목록에서 들락날락할 때마다 화면 전체가 재생성된다.**
10분 시뮬레이션에서 전선과 철판이 149회씩 들락거려 rebuild 가 151회 돌았다.

고친 것:

| | 전 | 후 |
|---|---|---|
| 10분간 전체 rebuild | 151회 | **3회** (품목이 처음 등장할 때만) |
| tick 1회 (320노드) | 6.15 ms | 4.67 ms |
| └ 그중 적자 경고 계산 | 2.40 ms | **0.68 ms** |

- 한 번이라도 보였던 품목은 0이 되어도 재고 목록에 남긴다. 목록이 단조 증가만 하므로
  rebuild 횟수가 품목 종류 수로 묶인다. 줄이 사라졌다 나타나지 않아 눈에도 낫다.
- 연결선 흐름 표시를 갱신할 때 `querySelectorAll` 로 SVG 를 매번 다시 뒤지지 않고,
  만들 때 모아 둔 목록을 쓴다.
- 노드·품목별 연결선 색인을 틱마다 한 번만 만든다. 예전에는 노드마다 전체 연결선을
  훑어서 노드 수 × 연결선 수가 됐다.

# 방치형 공장 게임 — 노드 일시 중지

노드 머리의 **⏸** 를 누르면 그 노드가 멈춘다. **멈춘 노드는 전력을 쓰지 않는다** — 이게 핵심이다.
기계는 그대로 남아 있고 버퍼도 유지되므로, ▶ 를 누르면 곧바로 다시 돈다.
멈춰 둔 노드는 자동 구매 대상에서도 빠진다.

## 왜 필요한가 — 스스로는 못 빠져나오는 상태가 있다

```
전력 355 / 221 MW   →  모든 기계 62%
  물 추출기 14%                    ← 전력이 모자라 느려진다
  석탄 발전기 90% "연료 부족: 물"   ← 물이 안 와서 발전량이 준다
  → 전력이 더 모자라진다
```

물을 뽑으려면 전력이 필요한데 전력을 만들려면 물이 필요하다. 이 고리는 안에서 끊을 수 없다.
기계를 팔면 자재가 절반만 돌아오고, 발전기를 더 지으려 해도 그 전에 공장이 기어간다.

**⚡ 전력 회복** 은 이 고리를 끊는다. 발전기와 그 연료를 만드는 라인(연결을 거꾸로 따라간 전부)은
지키고, 가장 하류(가장 가공된 쪽)부터 수요가 공급 밑으로 떨어질 때까지 멈춘다.
그 뒤 물·연료가 차오르면 ▶ 로 하나씩 되살리면 된다.

연료 라인 자체가 공급을 넘겨 쓰는 경우에는 멈출 수 있는 게 없으므로,
"아직 N MW 모자랍니다" 라고 알려 준다 — 그때는 발전기를 더 짓거나 연료 라인의 기계 수를 줄여야 한다.

새로 추가하는 노드는 **지금 보고 있는 화면 안의 빈 자리**에 생긴다 (예전에는 고정 격자에 생겨서 화면 밖에 배치되는 일이 있었다).

# 방치형 공장 게임 — 자동화

마일스톤 2(부품 조립)를 달성하면 사이드바에 **자동화** 패널이 열린다. 켜 둔 항목은 방치 중은 물론
오프라인 진행(최대 4시간) 동안에도 그대로 동작한다.

| 항목 | 동작 |
|---|---|
| 기계 자동 구매 | 각 노드의 🎯 목표 대수까지 재고로 알아서 구매 (재료가 모자라면 대기, 매장지 한도 초과 구매 안 함) |
| 마일스톤 자동 달성 | 재료가 모이는 즉시 다음 마일스톤 달성 |
| 벨트 자동 업그레이드 | 용량이 꽉 찬(포화) 연결선만 다음 티어로 업그레이드 — 여유 있는 벨트는 건드리지 않음 |
| 동력 조각 자동 구매 | 쿠폰 3장이 모이면 동력 조각으로 교환 (하드 드라이브는 대체 레시피 선택이 필요해 자동화 제외) |

**목표 대수(🎯)** 는 노드 아래 버튼으로 정한다. 0이면 그 노드는 자동 구매 대상에서 빠진다.
📋 계획 모드로 자동 배치하면 계산된 필요 대수가 🎯 에 자동으로 채워지므로,
`계획 모드 → 자동 배치 → 기계 자동 구매 ON` 만으로 라인 하나가 알아서 완성된다.

# 방치형 공장 게임 — 저장 서버

게임은 기본적으로 브라우저 localStorage에 저장되므로 기기를 옮기면 진행이 이어지지 않는다.
저장 서버를 띄우면 **플레이어 코드 8자리**로 어느 기기에서든 같은 저장을 이어서 할 수 있다.

## 실행 (Node 18+, 의존성 없음)

```powershell
node game\server.js            # http://localhost:8787/game/ 접속
$env:PORT=3000; node game\server.js
```

서버는 정적 파일(게임·플래너·아이콘)까지 함께 서빙하므로, 이 주소로 접속하면 그대로 플레이된다.
같은 네트워크의 다른 기기에서는 `http://<PC의 IP>:8787/game/` 로 접속한다.
외부(집 밖)에서도 하려면 이 서버를 VPS·Fly.io·Render 등에 올리거나 Cloudflare Tunnel 등으로 노출하면 된다.

## 다른 기기에서 이어서 하기

1. 서버로 접속하면 헤더에 `코드 ABCD-1234` 가 표시된다 (최초 접속 시 자동 발급).
2. 코드를 클릭하면 클립보드에 복사된다.
3. 다른 기기에서 같은 서버에 접속 → **코드 입력** 버튼 → 코드 붙여넣기 → 그 저장을 불러온다.

- 저장은 자동(10초 주기)·수동(저장 버튼)·탭 종료 시 서버로 전송된다.
- 서버 저장이 로컬보다 최신이면 접속 시 서버 쪽을 불러온다 (오프라인 진행도 서버 시각 기준으로 계산).
- 두 기기에서 동시에 플레이해 오래된 저장을 올리면 서버가 거부하고 `⚠ 충돌` 이 표시된다. 새로고침하면 최신 저장을 받는다.
- 서버가 꺼져 있거나 `game/index.html` 을 파일로 직접 열면 `💾 로컬 저장` 으로 표시되며 기존처럼 localStorage로 동작한다.
  파일로 열었을 때 서버를 쓰려면 **코드 입력** 버튼을 눌러 서버 주소(`http://호스트:8787`)를 먼저 등록한다.

> 코드는 아이디 겸 비밀번호 역할을 한다(계정·비밀번호 없음). 공개 인터넷에 올릴 계획이면 코드를 남과 공유하지 말 것.

저장 파일은 `game/saves/<코드>.json` 에 쌓인다 (`SAVE_DIR` 환경변수로 위치 변경 가능, git 추적 제외).

### API

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/api/save/new` | 새 플레이어 코드 발급 |
| GET | `/api/save/:code[/:slot]` | 저장 조회 (없으면 404) |
| PUT | `/api/save/:code[/:slot]` | 저장 (`{savedAt, state, force?}`, 서버가 더 최신이면 409) |
| DELETE | `/api/save/:code[/:slot]` | 저장 삭제 |

`:slot` 은 게임별 저장 칸이다 (생략 = `main` = 방치형 공장 게임, `rulefactory` = 규칙 공장).
코드 하나로 여러 게임의 저장을 따로 보관한다. 파일은 `game/saves/<코드>.json`,
`game/saves/<코드>__<슬롯>.json` 로 쌓인다.

# 공장 플래너

Satisfactory 1.0 전체 레시피(대체 레시피 111종 포함) 기반 생산 계획 웹 앱.
목표 아이템과 분당 생산량을 입력하면 생산 트리, 필요 기계 수, 원자재, 총 전력, 부산물을 계산한다.

## 실행

`web/index.html` 을 브라우저에서 열면 끝 (서버 불필요, 오프라인 동작).

## 사용법

1. 아이템 검색창에 한글 또는 영문명 입력 (자동완성, 예: `철판` / `Iron Plate`) → 분당 생산량 입력 → **추가**
2. 목표는 여러 개 추가 가능, 요약(전력·기계·원자재·부산물)은 전체 합산
3. 생산 트리의 각 단계에서 드롭다운으로 레시피 변경 가능 (★ = 대체 레시피)
   - 레시피 선택은 아이템 단위 전역 적용 (같은 아이템은 트리 전체에서 동일 레시피)
4. 순환 레시피(예: Recycled Plastic ↔ Recycled Rubber 상호 참조)는 `⟳ 순환` 으로 표시되고
   해당 지점은 외부 공급으로 간주

## 계산 기준

- 기계 클럭 100% 기준. 기계 수는 소수(정확값)와 올림값(대) 병기
- 전력: 기계 수(소수) × 기계 소비 전력. 가변 전력 기계(입자 가속기 등)는 min/max 평균 사용
- 부산물은 자동 재사용(netting) 계산하지 않고 별도 표시
- 채굴기/추출기 전력은 미포함 (생산 기계만)

## 구조

```
web/index.html   앱 진입점
web/app.js       계산 로직 + UI (의존성 없는 바닐라 JS)
web/style.css    다크 테마 스타일
web/data.js      게임 데이터 (build_data.py 로 생성, 한국어 명칭 포함)
tools/build_data.py   raw_data.json + raw_ko.json → web/data.js 변환 스크립트
raw_data.json    원본 게임 데이터 (SatisfactoryTools 1.0, data1.0.json)
raw_ko.json      공식 한국어 명칭 (satisfactory-calculator.com /ko/api/game)
game/icons/      아이템·건물 아이콘 168개 (tools/fetch_icons.py 로 다운로드)
game/server.js   저장 서버 (정적 서빙 + 저장 API, 의존성 없음)
game/cloud.js    클라이언트 동기화 계층 (코드 발급·불러오기·서버 저장)
```

## 데이터 갱신

게임 업데이트 시:

```powershell
# 영문 수치 데이터 (레시피·전력·시간)
curl.exe -sL -o raw_data.json "https://raw.githubusercontent.com/greeny/SatisfactoryTools/master/data/data1.0.json"
# 한국어 명칭: 브라우저에서 https://satisfactory-calculator.com/ko/api/game 응답을 raw_ko.json 으로 저장
python tools\build_data.py
```

아이템·기계·레시피 이름은 게임 공식 한국어 번역을 따른다 (예: 철판, 제작기, 대체: 주조된 나사).
한국어 데이터에 없는 항목은 영문명으로 표시된다.
