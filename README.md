  노드를 배치하고 출력→입력 포트를 드래그로 연결해 생산 체인을 설계한다 (버퍼·배압·전력
  부족 감속 시뮬레이션). 컨베이어 벨트 티어(Mk.1 60/분 ~ Mk.5 780/분, 연결선 클릭으로

  AWESOME 싱크(아이템 소각 → 포인트 → 쿠폰 자동 발행) + 상점(동력 조각·하드 드라이브),

  원자력 발전(2,500MW, 폐기물이 안 빠지면 정지 — 소각 불가라 재처리 라인 필수),
  채굴기 Mk.1~3(60/120/240, 마일스톤 해금), 노드 복제, 공장 통계 패널,
  계획 모드(목표 아이템 → 필요 라인 계산 → 캔버스 자동 배치),
  마일스톤 12개(프로젝트 조립 1~5단계), 시작 가이드, 효과음,
  자동화(기계 자동 구매·마일스톤 자동 달성·벨트 자동 업그레이드·동력 조각 자동 교환),

  localStorage 자동 저장 + 오프라인 진행(최대 4시간).
  `node game/server.js` 로 저장 서버를 띄우면 진행 상황이 서버에 저장되어
  다른 기기·다른 브라우저에서 이어서 할 수 있다 (아래 "저장 서버" 참고).

# 규칙 공장 (`rulefactory/`)

기존 게임이 "노드를 놓고 선을 잇는" 배치 게임이라면, 이쪽은 **규칙을 짜는 게임**이다.
플레이어는 기계를 직접 사지 않는다. `조건 → 행동` 규칙을 만들어 두면 컨트롤러가 대신 짓는다.

```
만약  재고   철 광석  <  400  이면  →  채취기 증설   철 광석 ×1   (쿨다운 8초)
만약  전력 여유(%)    <  15   이면  →  발전기 증설   석탄 발전기 ×1
만약  주기(초)마다    30            →  계약 납품
```

## 핵심 제약: 제어 대역폭

규칙은 매 틱 **위에서부터** 평가되고, 평가에 1 · 발동에 3 만큼 대역폭을 쓴다.
대역폭이 바닥나면 **아래쪽 규칙은 그 틱에 아예 평가되지 않는다** (화면에 "대역폭 부족"으로 표시).
따라서 이 게임의 실력은 *규칙 순서와 쿨다운 배분*이다. 대역폭은 연구로 늘린다.

- **조건**: 재고 · 순생산(/분) · 전력 여유(%) · 라인 가동률(%) · 크레딧 · N초 주기 · 항상
- **행동**: 생산 라인 증설 · 채취기 증설 · 발전기 증설 · 재고 소각(→크레딧) · 연구 구매 ·
  계약 납품 · **다른 규칙 켜기/끄기**(규칙이 규칙을 제어하는 메타 규칙)
- **성장**: 계약 납품 → 크레딧 → 연구(대역폭·규칙 슬롯·기계 해금) → 더 복잡한 규칙
- 오프라인(기본 4시간, 연구로 12시간) 동안에도 규칙이 그대로 돈다

## 시작

이 게임에는 수동 채집·수동 제작이 없으므로, 새로 시작하면 **시작 지원 물자**(철판·철봉·콘크리트·
전선·케이블·보강 철판)와 **철 광석 채취기 1대**가 주어진다. 규칙 패널의 **"예시 규칙 넣기"** 를 누르면
스스로 돌아가는 최소 순환(철·구리·석회석 채취 → 주괴 → 철판·철봉·콘크리트)이 8개 규칙으로 채워진다.
그대로 두면 30분쯤 뒤 1차 납품 수량에 도달한다. 이후는 수치를 바꾸고 규칙을 추가하며 키우면 된다.

채취기가 하나도 없고 채취기를 지을 자재도 없으면 새로 들어올 자원이 없어 영영 멈춘다.
그때만 공장 현황 패널에 **긴급 지원 물자** 버튼이 열린다 (막히지 않았을 때는 사용할 수 없다).

전력은 기본 100MW로 시작하며 기계 20대쯤이면 바닥난다 — 그 다음은 석탄 발전 연구가 필요하다.

저장은 기존 게임과 완전히 분리된다 (localStorage 키가 다르고, 서버 저장은 같은 코드의 다른 슬롯).
같은 플레이어 코드로 두 게임을 각각 이어서 할 수 있다.

# 방치형 공장 게임 — 배치 관리

공장이 커지면 캔버스가 금방 난장판이 된다. 툴바 오른쪽 세 버튼으로 정리한다.

| 버튼 | 동작 |
|---|---|
| 🧹 정리 | 연결 관계를 따라 원자재 → 가공 단계 → 출하 순으로 왼쪽부터 열을 맞춰 재배치 (직접 잡아둔 위치는 사라지므로 확인창을 띄운다) |
| ⤢ 화면 맞춤 | 모든 노드가 한 화면에 들어오도록 확대율과 스크롤을 맞춤 (최소 20%까지 축소) |
| 🔍 축소 표시 | 노드에서 건설 비용·속도·버퍼를 감추고 작게 표시 — 노드가 20개를 넘어가면 이쪽이 보기 편하다. 설정은 저장된다 |

새로 추가하는 노드는 **지금 보고 있는 화면 안의 빈 자리**에 생긴다 (예전에는 고정 격자에 생겨서 화면 밖에 배치되는 일이 있었다).

# 방치형 공장 게임 — 자동화

마일스톤 2(부품 조립)를 달성하면 사이드바에 **자동화** 패널이 열린다. 켜 둔 항목은 방치 중은 물론
오프라인 진행(최대 4시간) 동안에도 그대로 동작한다.

| 항목 | 동작 |
|---|---|
| 기계 자동 구매 | 각 노드의 🎯 목표 대수까지 재고로 알아서 구매 (재료가 모자라면 대기, 매장지 한도 초과 구매 안 함) |
| 마일스톤 자동 달성 | 재료가 모이는 즉시 다음 마일스톤 달성 |
| 벨트 자동 업그레이드 | 용량이 꽉 찬(포화) 연결선만 다음 티어로 업그레이드 — 여유 있는 벨트는 건드리지 않음 |
| 동력 조각 자동 구매 | 쿠폰 3장이 모이면 동력 조각으로 교환 (하드 드라이브는 대체 레시피 선택이 필요해 자동화 제외) |

**목표 대수(🎯)** 는 노드 아래 버튼으로 정한다. 0이면 그 노드는 자동 구매 대상에서 빠진다.
📋 계획 모드로 자동 배치하면 계산된 필요 대수가 🎯 에 자동으로 채워지므로,
`계획 모드 → 자동 배치 → 기계 자동 구매 ON` 만으로 라인 하나가 알아서 완성된다.

# 방치형 공장 게임 — 저장 서버

게임은 기본적으로 브라우저 localStorage에 저장되므로 기기를 옮기면 진행이 이어지지 않는다.
저장 서버를 띄우면 **플레이어 코드 8자리**로 어느 기기에서든 같은 저장을 이어서 할 수 있다.

## 실행 (Node 18+, 의존성 없음)

```powershell
node game\server.js            # http://localhost:8787/game/ 접속
$env:PORT=3000; node game\server.js
```

서버는 정적 파일(게임·플래너·아이콘)까지 함께 서빙하므로, 이 주소로 접속하면 그대로 플레이된다.
같은 네트워크의 다른 기기에서는 `http://<PC의 IP>:8787/game/` 로 접속한다.
외부(집 밖)에서도 하려면 이 서버를 VPS·Fly.io·Render 등에 올리거나 Cloudflare Tunnel 등으로 노출하면 된다.

## 다른 기기에서 이어서 하기

1. 서버로 접속하면 헤더에 `코드 ABCD-1234` 가 표시된다 (최초 접속 시 자동 발급).
2. 코드를 클릭하면 클립보드에 복사된다.
3. 다른 기기에서 같은 서버에 접속 → **코드 입력** 버튼 → 코드 붙여넣기 → 그 저장을 불러온다.

- 저장은 자동(10초 주기)·수동(저장 버튼)·탭 종료 시 서버로 전송된다.
- 서버 저장이 로컬보다 최신이면 접속 시 서버 쪽을 불러온다 (오프라인 진행도 서버 시각 기준으로 계산).
- 두 기기에서 동시에 플레이해 오래된 저장을 올리면 서버가 거부하고 `⚠ 충돌` 이 표시된다. 새로고침하면 최신 저장을 받는다.
- 서버가 꺼져 있거나 `game/index.html` 을 파일로 직접 열면 `💾 로컬 저장` 으로 표시되며 기존처럼 localStorage로 동작한다.
  파일로 열었을 때 서버를 쓰려면 **코드 입력** 버튼을 눌러 서버 주소(`http://호스트:8787`)를 먼저 등록한다.

> 코드는 아이디 겸 비밀번호 역할을 한다(계정·비밀번호 없음). 공개 인터넷에 올릴 계획이면 코드를 남과 공유하지 말 것.

저장 파일은 `game/saves/<코드>.json` 에 쌓인다 (`SAVE_DIR` 환경변수로 위치 변경 가능, git 추적 제외).

### API

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/api/save/new` | 새 플레이어 코드 발급 |
| GET | `/api/save/:code[/:slot]` | 저장 조회 (없으면 404) |
| PUT | `/api/save/:code[/:slot]` | 저장 (`{savedAt, state, force?}`, 서버가 더 최신이면 409) |
| DELETE | `/api/save/:code[/:slot]` | 저장 삭제 |

`:slot` 은 게임별 저장 칸이다 (생략 = `main` = 방치형 공장 게임, `rulefactory` = 규칙 공장).
코드 하나로 여러 게임의 저장을 따로 보관한다. 파일은 `game/saves/<코드>.json`,
`game/saves/<코드>__<슬롯>.json` 로 쌓인다.

# 공장 플래너

Satisfactory 1.0 전체 레시피(대체 레시피 111종 포함) 기반 생산 계획 웹 앱.
목표 아이템과 분당 생산량을 입력하면 생산 트리, 필요 기계 수, 원자재, 총 전력, 부산물을 계산한다.

## 실행

`web/index.html` 을 브라우저에서 열면 끝 (서버 불필요, 오프라인 동작).

## 사용법

1. 아이템 검색창에 한글 또는 영문명 입력 (자동완성, 예: `철판` / `Iron Plate`) → 분당 생산량 입력 → **추가**
2. 목표는 여러 개 추가 가능, 요약(전력·기계·원자재·부산물)은 전체 합산
3. 생산 트리의 각 단계에서 드롭다운으로 레시피 변경 가능 (★ = 대체 레시피)
   - 레시피 선택은 아이템 단위 전역 적용 (같은 아이템은 트리 전체에서 동일 레시피)
4. 순환 레시피(예: Recycled Plastic ↔ Recycled Rubber 상호 참조)는 `⟳ 순환` 으로 표시되고
   해당 지점은 외부 공급으로 간주

## 계산 기준

- 기계 클럭 100% 기준. 기계 수는 소수(정확값)와 올림값(대) 병기
- 전력: 기계 수(소수) × 기계 소비 전력. 가변 전력 기계(입자 가속기 등)는 min/max 평균 사용
- 부산물은 자동 재사용(netting) 계산하지 않고 별도 표시
- 채굴기/추출기 전력은 미포함 (생산 기계만)

## 구조

```
web/index.html   앱 진입점
web/app.js       계산 로직 + UI (의존성 없는 바닐라 JS)
web/style.css    다크 테마 스타일
web/data.js      게임 데이터 (build_data.py 로 생성, 한국어 명칭 포함)
tools/build_data.py   raw_data.json + raw_ko.json → web/data.js 변환 스크립트
raw_data.json    원본 게임 데이터 (SatisfactoryTools 1.0, data1.0.json)
raw_ko.json      공식 한국어 명칭 (satisfactory-calculator.com /ko/api/game)
game/icons/      아이템·건물 아이콘 168개 (tools/fetch_icons.py 로 다운로드)
game/server.js   저장 서버 (정적 서빙 + 저장 API, 의존성 없음)
game/cloud.js    클라이언트 동기화 계층 (코드 발급·불러오기·서버 저장)
```

## 데이터 갱신

게임 업데이트 시:

```powershell
# 영문 수치 데이터 (레시피·전력·시간)
curl.exe -sL -o raw_data.json "https://raw.githubusercontent.com/greeny/SatisfactoryTools/master/data/data1.0.json"
# 한국어 명칭: 브라우저에서 https://satisfactory-calculator.com/ko/api/game 응답을 raw_ko.json 으로 저장
python tools\build_data.py
```

아이템·기계·레시피 이름은 게임 공식 한국어 번역을 따른다 (예: 철판, 제작기, 대체: 주조된 나사).
한국어 데이터에 없는 항목은 영문명으로 표시된다.
