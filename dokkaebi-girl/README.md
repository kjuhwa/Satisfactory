# 도깨비 소녀와 함께 — 웹 프로토타입

네이버 게임 라운지의 [도깨비 소녀와 함께](https://game.naver.com/lounge/Dokkaebi_Girl/home)(모바일 방치형 수집 RPG)를
역설계해 핵심 루프만 단일 HTML 파일로 재구성한 습작입니다.

## 실행

`index.html`을 브라우저로 열면 끝입니다. 빌드·의존성 없음. 진행 상황은 `localStorage`에 저장됩니다.

## 원작 분석 — 무엇을 옮겼나

원작의 뼈대는 **다축 강화 → 단일 전투력(CP) → 스테이지 게이트**입니다.
성장 수단이 장비/신기/탈것/날개/승급/호감도로 여러 갈래지만 전부 CP 하나로 수렴하고,
그 CP가 층 보스라는 관문을 여는 구조입니다. 이 뼈대를 그대로 가져왔습니다.

| 원작 | 프로토타입 |
|---|---|
| 메인 스테이지 자동 전투 | 초당 DPS 자동 적용, 10킬마다 층 상승 |
| 직관적인 몽둥이 조작 전투 | 탭 시 공격력 ×2.5 추가타 (치명타 판정 포함) |
| 층 보스 | 10층마다 HP ×8 · 제한시간 30초 — 실패 시 재도전 |
| 캐릭터 수집 (여우/직장인/아이돌/게이머…) | 10종 도깨비, N/R/SR/SSR 4등급 소환 |
| 중복 → 조각 → 승급 | 중복 시 조각 전환, ★1~5 (별당 +20%) |
| 호감도 시스템 | 어패·약초 선물로 Lv.0~10 (단계당 +5%) |
| 신기·탈것·날개 강화 | 장비 5종, 레벨당 고정 스탯 |
| 영지 낚시·재배 | 낚시터/텃밭 자동 생산, 미접속 중에도 누적 |
| 월드보스 누적 피해 랭킹 | 30초 도전, 서버 랭킹 보드 |
| 방치 보상 | 최대 8시간 오프라인 정산 |

**옮기지 않은 것**: 학생회(길드), 아레나 PvP, 출항, 스토리, 결제.

## 설계 노트 — 왜 환생을 추가했나

원작에는 없는 축을 하나 넣었습니다. 이유는 수치에서 나왔습니다.

장비 강화는 비용이 지수(×1.10/레벨)로 오르므로 도달 가능 레벨은 골드의 로그,
따라서 **DPS는 층수에 대해 선형**으로만 자랍니다. 반면 몬스터 HP는 **지수(×1.13/층)** 입니다.
시뮬레이션 결과 어떤 파라미터를 써도 60층 부근에서 완전 정체했습니다.

```
HP^1.13 골드^1.15 비용^1.10 → 10분 34층 / 30분 40층 / 60분 44층 / 8시간 60층 (정체)
```

캐릭터 승급·호감도는 **상수 배율**이라 벽을 8층 정도밖에 밀지 못합니다.
원작은 이 지점을 뽑기와 결제로 메우지만, 프로토타입에서는 장르의 정공법인
프레스티지를 넣어 해결했습니다 — 정수 1개당 공격력 ×1.18(지수), 25층 초과분의 0.6배 지급.

정수 배율을 바꿔가며 재시뮬한 결과:

| 정수 배율 | 30분 | 1시간 | 2시간 | 4시간 |
|---|---|---|---|---|
| ×1.18 | 60층 | 100층 | 161층 | 180층에서 안정 |
| ×1.22 | 74층 | 139층 | 336층 | 687층 (폭주) |
| ×1.26 | 86층 | 179층 | 575층 | 2190층 (폭주) |

×1.18은 층당 실효 성장률이 HP 성장률과 거의 균형을 이뤄, 계속 나아가되 폭주하지 않습니다.
위 수치는 **캐릭터 성장을 전부 제외한 하한선**이므로 실제 플레이는 이보다 빠릅니다.

## 주요 수식

```js
mobHp(층)   = 60  × 1.13^(층-1) × (보스면 ×8)
mobGold(층) = 14  × 1.15^(층-1) × (보스면 ×10)
장비비용     = base × 1.10^(레벨-1) × (1 - 무쇠 특성)
공격력       = (기본 + 장비 + 파티) × (1 + 세라 특성) × 1.18^정수
DPS         = 공격력 × (1 + 치명확률 × (치명피해 - 1))
정수         = floor(max(0, 최고층 - 25) × 0.6)
```

## 파일

- `index.html` — 게임 전체 (단일 파일, ~800줄)

## 확인한 것

- Chrome에서 구동, 콘솔 에러 없음
- 소환 → 파티 편성 → 강화 → 영지 → 호감도 → 승급 → 월드보스 → 환생 전 경로 동작
- 탭이 백그라운드로 내려가면 브라우저가 rAF를 정지시키므로,
  복귀 시 `visibilitychange`에서 그 공백을 방치 보상으로 정산
- 월드보스 타이머는 틱 수가 아닌 실제 경과 시간 기준 (백그라운드 throttle 대응)
